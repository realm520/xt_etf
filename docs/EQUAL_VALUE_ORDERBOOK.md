# 等价值订单簿系统

## 📋 功能概述

等价值订单簿系统提供了一种新的订单分布策略，确保每个订单档位占用相同的USDT价值，从而实现更均衡的资金利用。

## 🎯 核心优势

### 1. **资金利用均衡**
- **原始订单簿（指数递增）**:
  - 近端订单: ~1 USDT
  - 远端订单: ~78 USDT（远端占用资金是近端的78倍！）
  - 总占用: ~1231 USDT（60档）

- **等价值订单簿**:
  - 每档订单: 固定2 USDT
  - 总占用: 120 USDT（60档）
  - **资金节省: 90.3%** ✅

### 2. **盘口深度稳定**
- 所有价格档位的市场影响力相同
- 避免远端订单过度占用资金
- 减少因资金不足导致的盘口缺失

### 3. **风险可控**
- 支持总预算限制
- 自动调整订单金额以适应预算约束
- 详细的资金使用日志

## 🔧 配置方法

### 1. 启用等价值订单簿

在 `config/strategies.yaml` 中添加以下配置：

```yaml
ton3l:  # 策略名称
  symbol: "TON3LUSDT"

  # ✅ 启用等价值订单簿
  use_equal_value_orderbook: true

  # ✅ 每档订单目标金额（USDT）
  target_value_per_order: 2.0

  # ✅ 总预算限制（可选，USDT）
  total_order_budget: 200  # 设置总预算上限

  # 订单档位数（可选，默认30）
  layer: 30

  # 其他配置...
  bid_ask_spread: 0.01
```

### 2. 配置参数说明

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `use_equal_value_orderbook` | bool | `false` | 是否启用等价值订单簿 |
| `target_value_per_order` | float | `2.0` | 每个订单的目标金额（USDT） |
| `total_order_budget` | float | `None` | 总预算限制（USDT），`null`表示不限制 |
| `layer` | int | `30` | 订单档位数（买卖各N档） |

### 3. 资金预算计算

**理论总需求**:
```
total_required = target_value_per_order × (买档数 + 卖档数)
               = 2.0 × (30 + 30)
               = 120 USDT
```

**预算不足时的自动调整**:
```python
if total_required > total_budget:
    adjusted_value = total_budget / (买档数 + 卖档数)
    # 例如：500 USDT预算不足，自动调整为 80 / 60 = 1.33 USDT/档
```

## ⚠️ 注意事项

### 1. 精度问题
- 极高价格资产（>10000 USDT）可能导致数量过小（<1e-8），系统会自动跳过
- 建议：高价资产使用更大的 `target_value_per_order`

### 2. 最小订单金额
- 确保 `target_value_per_order` 大于交易所最小订单金额（通常1.2 USDT）
- 系统会自动验证并调整

### 3. 预算管理
- 建议设置 `total_order_budget` 避免资金过度占用
- 预算不足时会自动调整，但可能影响盘口深度

### 4. 性能影响
- 等价值订单簿计算量略高于原始方法
- 但对整体性能影响可忽略（<1ms差异）

## 🐛 常见问题

### Q1: 为什么订单总金额为0？
**A**: 价格过高导致计算的币数量低于精度阈值（<1e-8），系统自动跳过。
**解决方案**: 增大 `target_value_per_order` 或检查交易对配置。

### Q2: 预算不足时会自动调整吗？
**A**: 是的！系统会自动计算并调整每档订单金额以适应预算约束，同时记录警告日志。

### Q3: 等价值订单簿会影响性能吗？
**A**: 几乎没有影响。额外的计算时间<1ms，可忽略不计。

### Q4: 如何监控资金使用情况？
**A**: 查看日志中的 "📊 等价值订单簿生成完成" 消息，包含详细的资金占用信息。
