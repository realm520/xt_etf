# TON3S 挂单超900档问题修复

## 📋 问题描述

**时间**: 2025-11-23
**策略**: ton3s (TON 3x 做空)
**症状**: 挂单数量超过 900 档，远超预期

## 🔍 根本原因

### 配置差异对比

| 策略 | orderbook_algorithm | 实际行为 | 挂单数量 |
|------|---------------------|----------|----------|
| **ton3l** | ✅ `natural` | 新订单簿算法，智能管理 | ~60档 (正常) |
| **ton3s** | ❌ 未配置 | 旧订单簿逻辑，累积堆积 | >900档 (异常) |

### 累积机制

从日志分析：
```
2025-11-23 12:59:09 | 订单操作计划 - 新增: 59, 取消: 3
2025-11-23 12:59:30 | 订单操作计划 - 新增: 60, 取消: 3
2025-11-23 13:00:22 | 订单操作计划 - 新增: 2, 取消: 92
```

**问题模式**:
1. ❌ 每次更新：新增 60档，仅取消 3档
2. ❌ 净值小幅波动 → 10秒生成新订单
3. ❌ 旧订单未清理 → 持续累积
4. ⏱️ 运行几小时 → 900+ 档订单

### 为什么 ton3l 正常？

ton3l 使用新订单簿算法 (`orderbook_algorithm: "natural"`)：
- ✅ **智能差异更新**: 只修改变化的档位
- ✅ **总量控制**: 始终维持 ~60档 (layer=500的算法优化结果)
- ✅ **高效取消**: 自动清理无效订单

## ✅ 解决方案

### 修改内容

**文件**: `config/strategies.yaml`
**策略**: ton3s
**变更**: 添加 `orderbook_algorithm` 配置

```yaml
ton3s:
  # ... 其他配置 ...

  # ========== 新订单簿算法配置 ==========
  # ✅ 启用新订单簿系统（与ton3l保持一致）
  orderbook_algorithm: "natural"     # 使用自然盘口算法
  orderbook_config:
    total_budget: 10000.0            # 总预算 10000 USDT
    layer: 500                       # 总档位500档（买250 + 卖250，对称）
    extra_params:
      naturalness: "high"            # 高自然度（95%真实性）

  # 旧订单簿配置（保留向后兼容）
  orderbook:
    min_order_value: 20.0
    init_amount_multiplier: 1.5
    amount_growth_rate: 0.08
    layer: 30
```

### 预期效果

修复后的 ton3s 将表现为：
- ✅ 挂单数量: ~60档 (与ton3l一致)
- ✅ 订单更新: 高效差异更新
- ✅ 资源占用: 显著降低
- ✅ 系统稳定性: 提升

## 🎯 技术要点

### 新订单簿算法优势

1. **自然盘口模拟**
   - 95% 真实性 (naturalness: "high")
   - 符合真实交易所盘口分布
   - 避免被识别为机器挂单

2. **智能预算管理**
   - 总预算: 10000 USDT
   - 自动分配到 500档 (layer参数)
   - 实际档位数根据价格和精度优化

3. **高效更新机制**
   - 差异对比算法
   - 最小化订单操作
   - 降低交易所API压力

### 配置参数说明

| 参数 | 值 | 说明 |
|------|-----|------|
| `orderbook_algorithm` | `"natural"` | 使用自然盘口算法 |
| `total_budget` | `10000.0` | 总挂单预算 (USDT) |
| `layer` | `500` | 目标档位数 (实际会优化) |
| `naturalness` | `"high"` | 盘口自然度等级 |
