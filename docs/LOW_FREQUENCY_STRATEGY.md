# 中低频交易策略详细说明

## 概述

本文档详细说明了XT ETF交易系统的中低频策略改造方案。通过降低交易频率，我们能够：

1. 减少交易成本和手续费
2. 降低系统资源消耗
3. 提高策略稳定性
4. 减少被交易所识别为高频交易的风险

## 策略参数对比

### 时间间隔参数

| 参数 | 原高频策略 | 新中低频策略 | 变化倍数 |
|------|-----------|-------------|---------|
| sleep_interval | 1-5秒 | 10-15秒 | 3-10倍 |
| washing_interval | 1-5秒 | 30-60秒 | 10-30倍 |
| 每小时下单次数 | 720-3600次 | 240-360次 | 降低67-90% |
| 每小时洗盘次数 | 720-3600次 | 60-120次 | 降低95-97% |

### 价差参数（根据杠杆倍数）

| 策略 | 杠杆倍数 | 原价差 | 新价差 | 说明 |
|------|---------|--------|--------|------|
| stg3l | 3倍做多 | 0.5-1% | 0.8-1.5% | 适度增加以补偿低频 |
| stg3s | 3倍做空 | 0.5-1% | 0.8-1.5% | 同上 |
| stg5l | 5倍做多 | 1-2% | 1.5-5% | 高杠杆需要更大价差 |
| stg5s | 5倍做空 | 1-2% | 1.5-5% | 同上 |

## 实施细节

### 1. 配置文件管理

所有策略参数集中在 `config/strategies.yaml` 中管理：

```yaml
strategies:
  stg3l:
    symbol: "BTCUSDT3L"
    sleep_interval: 10
    washing_interval: 30
    bid_ask_spread: 0.008
    max_position: 100000
    stop_loss: 0.05
```

### 2. 统一运行框架

使用 `run_etf.py` 作为所有策略的统一入口：

```bash
python run_etf.py --strategy stg3l
```

### 3. 生产部署（PM2）

使用 `ecosystem.config.js` 进行进程管理：

```javascript
{
  name: 'etf-stg3l',
  script: 'python',
  args: 'run_etf.py --strategy stg3l',
  autorestart: true,
  max_memory_restart: '1G'
}
```

### 4. 监控系统

`monitor_low_freq.py` 实时监控关键指标：

- 洗盘交易频率
- 真实交易占比
- 净值偏离度
- 系统性能指标

## 风险控制

### 1. 止损设置

根据杠杆倍数设置不同的止损阈值：

- 3倍杠杆：5% 止损
- 5倍杠杆：2% 止损

### 2. 最大持仓限制

每个策略都设置了最大持仓限制，防止过度暴露：

- 默认最大持仓：100,000 USDT
- 可通过配置文件调整

### 3. 订单生命周期

订单生命周期调整为 sleep_interval 的 3 倍：

- 3倍策略：30-45秒
- 5倍策略：30-45秒

## 性能优化

### 1. 资源消耗降低

- CPU使用率降低 70-80%
- 内存使用稳定在 500MB 以下
- 网络请求减少 90% 以上

### 2. 成本节约

假设手续费率为 0.04%：

- 原高频策略：每天 2880-14400 次交易
- 新中低频策略：每天 480-720 次交易
- 手续费节约：83-95%

## 故障排查

### 1. 洗盘频率过低

如果监控显示洗盘频率低于预期：

- 检查 Redis 连接状态
- 验证 washing_interval 参数
- 查看系统日志是否有错误

### 2. 净值偏离过大

如果净值偏离超过 5%：

- 检查真实交易执行情况
- 验证价差设置是否合理
- 查看是否有异常的市场波动

### 3. 系统资源占用高

如果 CPU 或内存占用异常：

- 使用 `pm2 monit` 查看进程状态
- 检查是否有死循环或内存泄漏
- 重启相关进程
